# 数据字典（DFD 配套）

> 配套图：`DFD-顶层图.png`、`DFD-0层图.png`、`DFD-1层图-P2读取权限菜单.png`、`DFD-1层图-P4执行功能按钮.png`
> 本字典与数据流图一一对应：**图上有几条流，这里就有几条条目**。

---

## 一、数据元素条目（最小数据单元）

| 数据元素 | 类型 | 长度 | 取值范围 | 说明 |
|---|---|---|---|---|
| user_id | 整数 | 4 字节 | 自增 | 用户唯一标识 |
| username | 字符 | ≤50 | 字母数字 | 登录名，全局唯一 |
| password | 字符 | 88 | `pbkdf2_sha256$…` 或明文（演示） | 口令 |
| major | 字符 | ≤50 | — | 专业 |
| grade | 字符 | ≤20 | 如「2024级」 | 年级 |
| role_id | 整数 | 4 字节 | 1/2/3 | 1=授课教师 2=助教 3=学生 |
| role_name | 字符 | ≤50 | 授课教师/助教/学生 | 角色名 |
| menu_id | 整数 | 4 字节 | 1~8（可扩展） | 功能点（= 权限点）唯一标识 |
| menu_name | 字符 | ≤50 | 查看考勤/发布作业… | 按钮文字 |
| menu_url | 字符 | ≤200 | `room.html#menu-N` | 前端页面 + 元素锚点 |
| course_id | 整数 | 4 字节 | 自增 | 课程唯一标识 |
| member_id | 整数 | 4 字节 | 自增 | 课堂成员记录标识（课程 × 用户） |
| record_id | 整数 | 8 字节 | 自增 | 聊天记录标识 |
| content | 字符 | ≤2000 | — | 记录正文（含【菜单名】前缀） |
| token | 字符 | 32 | 十六进制 | 登录凭证（会话 ID） |
| status_code | 整数 | 4 字节 | 200/401/403 | 接口结果码 |

---

## 二、数据结构条目（若干数据元素的组合）

| 数据结构 | 组成 |
|---|---|
| **用户记录** | user_id + username + password + major + grade |
| **角色记录** | role_id + role_name |
| **菜单记录** | menu_id + menu_name + menu_url |
| **课堂成员记录** | member_id + course_id + user_id + role_id |
| **课程记录** | course_id + course_name + class_time + classroom + hours + credits |
| **聊天记录** | record_id + member_id + menu_id + content |
| **可用按钮列表** | { menu_id + menu_name + menu_url }（0…N 条） |
| **登录凭证** | token + 过期时间 |

## 三、数据流条目

### 3.1 顶层图 / 0 层图

| 编号 | 数据流名 | 来源 → 去向 | 组成 |
|---|---|---|---|
| F1 | 用户名 / 密码 | 用户 → P1 | username + password |
| F2 | 登录凭证 | P1 → 用户 | token |
| F3 | 课程ID + 凭证 | 用户 → P2 | course_id + token |
| F4 | 本课身份 + 可用按钮 | P2 → 用户 | role_name + { menu_id, menu_name, menu_url } |
| F5 | 聊天室ID + 凭证 | 用户 → P3 | room_id + token |
| F6 | 消息流 | P3 → 用户 | { record_id, username, role_name, menu_id, menu_name, content } |
| F7 | menu_id + 输入内容 | 用户 → P4 | menu_id + content + token |
| F8 | 执行结果 / 403 | P4 → 用户 | status_code + record_id 或错误原因 |
| F9 | 用户记录查询 | D1 → P1 | 用户记录 |
| F10 | 本课角色 role_id | D4 → P2 | member_id + role_id + role_name |
| F11 | 角色权限菜单 | D3 → P2 | { menu_id, menu_name, menu_url } |
| F12 | 课程 / 聊天室 | D6 → P2 | course_id + course_name + class_time + classroom + room_id |
| F13 | 我的全局角色 | D2 → P2 | { role_id, role_name } |
| F14 | 聊天记录 | D5 → P3 | { record_id, member_id, menu_id, content } |
| F15 | 校验本课角色 | D4 → P4 | role_id |
| F16 | 校验 role_menu | D3 → P4 | menu_id（命中/未命中） |
| F17 | 新记录写入 | P4 → D5 | member_id + menu_id + content（+ room_id） |

### 3.2 P4 的 1 层图（新增内部流）

| 编号 | 数据流名 | 来源 → 去向 | 组成 |

| F19 | 通过 + 菜单名 | P4.2 → P4.3 | menu_name（校验通过时才有） |

## 四、数据存储条目

| 编号 | 文件名 | 组成 | 主键 / 唯一键 | 读写它的处理 | 与数据库对应 |
|---|---|---|---|---|---|
| D1 | user | 用户记录 | user_id；username 唯一 | P1 读 | `user` |
| D2 | role / user_role | 角色记录 + (user_id, role_id) | role_id；(user_id, role_id) 唯一 | P2 读 | `role`、`user_role` |
| D3 | menu / role_menu | 菜单记录 + (role_id, menu_id) | menu_id；(role_id, menu_id) 唯一 | P2 读、P4.2 读 | `menu`、`role_menu` |
| D4 | class_member | 课堂成员记录 | member_id；(course_id, user_id) 唯一 | P2.1 读、P4.1 读 | `class_member` |
| D5 | chat_record / chat_room_record | 聊天记录 + (room_id, record_id) | record_id；(room_id, record_id) 联合主键 | P3 读、P4.4 写 | `chat_record`、`chat_room_record` |
| D6 | course / chat_room | 课程记录 + (room_id, course_id) | course_id；room_id | P2.3 读 | `course`、`chat_room` |

> 现库存量（演示数据）：D1 30 条、D2 31 条、D3 8 + 12 条、D4 36 条、D5 90 + 90 条、D6 3 + 3 条。

## 五、处理条目（小说明）

| 编号 | 处理名 | 输入 | 输出 | 处理逻辑 |
|---|---|---|---|---|
| **P1** | 身份认证 | F1 | F2、F9 | 按 username 查 D1；校验 password；生成 token 写入会话；失败返回 401 |
| **P2** | 读取权限菜单 | F3 | F4、F10、F11、F12、F13 | ①按 (course_id, user_id) 查 D4 得 role_id；②按 role_id 查 D3 得菜单；③查 D6 补课程信息；④组装返回 |
| **P3** | 查询聊天记录 | F5 | F6、F14 | 校验成员身份后，按 room_id 查 D5，联结 D4 取得作者与角色，按 record_id 升序返回 |
| **P4** | 执行功能按钮 | F7 | F8、F17 | 见下方分解 |
| **P4.1** | 校验本课角色 | F7、F10 | F18 | 查 D4：当前用户是否为本课成员；不是 → 403 |
| **P4.2** | 校验权限菜单 | F18、F15、F16 | F19 **或 F21** | 查 D3：该 role_id 是否被授予该 menu_id；未授予 → **403 并终止** |
| **P4.3** | 组装记录内容 | F19、F7 | F20 | `content = 「【」+menu_name+「】」+ 输入文字`；输入为空则填「已执行」 |
| **P4.4** | 写入聊天记录 | F20 | F8、F17 | 向 D5 插入 chat_record，再插入 chat_room_record 建立归属；返回 record_id |
| **P2.1** | 读取本课角色 | F3 | F10、F22 | 查 D4 |
| **P2.2** | 读取角色权限菜单 | F22 | F11、F23 | 查 D3 |
| **P2.3** | 组装界面数据 | F23、F12 | F4 | 合并身份、按钮列表、课程信息 |

## 六、两条必须能自圆其说的约束

1. **父子图平衡**：顶层图有 4 条输入流（F1、F3、F5、F7）、4 条输出流（F2、F4、F6、F8），在 0 层分别由 P1、P2、P3、P4 接收与产出；
   P2 / P4 的 1 层图输入输出与 0 层对应项完全一致（F3→F4；F7→F8）。
2. **写入前必须校验**：F17（写 D5）只可能由 P4.4 产生，而 P4.4 的唯一入口流 F20 来自 P4.3，其唯一入口 F19 来自 P4.2 的**成功分支**。
   因此**越权请求在数据流图上根本走不到写操作** —— 这就是「前端隐藏按钮 ≠ 安全」的数据流级证明。
